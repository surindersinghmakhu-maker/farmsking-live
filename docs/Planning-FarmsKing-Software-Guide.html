ਭਾਗ 2: FarmsKing ਵਿੱਚ ਕੀ ਗਲਤੀਆਂ ਹੋਈਆਂ

ਆਲੋਚਨਾ ਲਈ ਨਹੀਂ — ਸਿੱਖਣ ਲਈ ਹਨ

⚠️ ਇਹ ਗੱਲਾਂ ਸਿਰਫ਼ ਸਿੱਖਣ ਲਈ ਲਿਖੀਆਂ ਹਨ। ਤੁਸੀਂ ਇਕੱਲੇ ਜੋ ਕੀਤਾ ਉਹ ਬਹੁਤ impressive ਹੈ।
1
Design ਤੋਂ ਪਹਿਲਾਂ Code ਸ਼ੁਰੂ
🔴 ਸਮੱਸਿਆ: ਕੋਈ Figma Design ਨਹੀਂ, ਸਿੱਧਾ Code ਲਿਖਣਾ ਸ਼ੁਰੂ
⚠️ ਨਤੀਜਾ: UI inconsistencies, ਵਾਰ-ਵਾਰ redesign, ਸਮਾਂ ਬਰਬਾਦ
✅ ਸਹੀ: ਪਹਿਲਾਂ Figma ਵਿੱਚ ਹਰ screen ਬਣਾਓ, ਫਿਰ code
2
Live Hotfixes ਸਿੱਧੇ Production ਤੇ
🔴 ਸਮੱਸਿਆ: ਸਿੱਧਾ npm run deploy → Blank Screen, Crashes
⚠️ ਨਤੀਜਾ: Users ਦਾ ਭਰੋਸਾ ਟੁੱਟਦਾ, ਡਾਟਾ ਖਤਰੇ ਵਿੱਚ
✅ ਸਹੀ: dev → staging → production pipeline, ਕਦੇ ਸਿੱਧਾ prod ਤੇ ਨਾ ਲਿਖੋ
3
ਕੋਈ Testing ਨਹੀਂ
🔴 ਸਮੱਸਿਆ: ਕੋਈ Unit tests, Integration tests ਨਹੀਂ
⚠️ ਨਤੀਜਾ: ਇੱਕ ਚੀਜ਼ ਠੀਕ ਕਰੋ, ਦੂਜੀ ਟੁੱਟ ਜਾਂਦੀ ਹੈ (more.tsx ਵਰਗੀਆਂ ਸਮੱਸਿਆਵਾਂ)
✅ ਸਹੀ: ਹਰ feature ਲਈ ਘੱਟੋ-ਘੱਟ 1 test ਲਿਖੋ
4
Code ਬਹੁਤ ਜਲਦੀ ਬਦਲਣਾ
🔴 ਸਮੱਸਿਆ: ਇੱਕੋ ਦਿਨ GARDENER hide → ਵਾਪਸ → hide
⚠️ ਨਤੀਜਾ: Broken logic, syntax errors, confusion
✅ ਸਹੀ: Feature Flags ਵਰਤੋ, ਪਹਿਲਾਂ ਸੋਚੋ ਫਿਰ implement
5
Database Schema ਬਿਨਾਂ Planning
🔴 ਸਮੱਸਿਆ: Roles ਸਭ ਬਾਅਦ ਵਿੱਚ ਜੋੜੇ ਗਏ
⚠️ ਨਤੀਜਾ: assignedRoles, deactivatedRoles — ਸਭ patches
✅ ਸਹੀ: ਪਹਿਲਾਂ ERD (Entity Relationship Diagram) ਬਣਾਓ
6
Security Concerns
🔴 ਸਮੱਸਿਆ: API Keys, Firebase Config code ਵਿੱਚ
⚠️ ਨਤੀਜਾ: Public repository ਤੇ secrets leak
✅ ਸਹੀ: .env ਫ਼ਾਈਲਾਂ, GitHub Secrets ਵਰਤੋ
7
ਕੋਈ Documentation ਨਹੀਂ
🔴 ਸਮੱਸਿਆ: ਕੋਈ API docs, README, onboarding guide ਨਹੀਂ
⚠️ ਨਤੀਜਾ: ਅਗਲੇ Developer ਨੂੰ ਸ਼ੁਰੂ ਤੋਂ ਸਮਝਣਾ ਪਵੇਗਾ
✅ ਸਹੀ: Swagger (API docs), Architecture diagrams, README
👤

□ Analytics ਦੇਖੋ

📋 Solo Developer — 7 ਜ਼ਰੂਰੀ Rules

  • 1
    main branch ਤੇ ਸਿੱਧਾ push ਨਾ ਕਰੋ — ਹਮੇਸ਼ਾ feature branch → PR → merge
  • 2
    Staging Environment ਜ਼ਰੂਰ ਰੱਖੋ — dev.farmsking.in ਤੇ test, ਫਿਰ prod
  • 3
    ਰੋਜ਼ commit ਕਰੋ, ਛੋਟੇ-ਛੋਟੇ — ਇੱਕ ਵੱਡਾ commit = ਸਭ ਕੁਝ ਟੁੱਟਣ ਦਾ ਡਰ
  • 4
    ਹਰ Feature ਲਈ ਘੱਟੋ-ਘੱਟ 1 Test — ਥੋੜ੍ਹਾ ਸਮਾਂ ਲੱਗਦਾ, ਬਾਅਦ ਵਿੱਚ ਬਚਾਉਂਦਾ
  • 5
    .env ਕਦੇ GitHub ਤੇ push ਨਾ ਕਰੋ — .gitignore ਵਿੱਚ ਜ਼ਰੂਰ ਸ਼ਾਮਲ ਕਰੋ
  • 6
    Database Backup ਰੋਜ਼ — PostgreSQL auto-backup ਸੈੱਟ ਕਰੋ
  • 7
    Documentation ਲਿਖੋ ਜਦੋਂ ਬਣਾਓ — ਬਾਅਦ ਵਿੱਚ ਭੁੱਲ ਜਾਵੋਗੇ

ਭਾਗ 4: ਜੇਕਰ FarmsKing ਦੁਬਾਰਾ ਸ਼ੁਰੂ ਕਰਦੇ

ਸਹੀ ਕ੍ਰਮ ਅਤੇ Timeline

Week 1 → User Research (20 Farmers ਨਾਲ Interview) Week 2-3 → Design System (Figma: Colors, Fonts, 10 Main Screens) Week 4 → Database Schema (Users, Farms, Crops, Records, Payments) Month 2-3 → Backend API (Auth ✓, Farm CRUD ✓, Swagger docs ✓) Month 4-5 → Frontend (React Native, Design ਤੋਂ ਸਿੱਧਾ code) Month 6 → Beta (50 Farmers) → Feedback → Fix → Launch 🚀
✅ Key Principle: "ਪਹਿਲਾਂ ਸਮਝੋ, ਫਿਰ Design ਕਰੋ, ਫਿਰ Code ਕਰੋ" — ਇਹ ਕ੍ਰਮ ਕਦੇ ਨਾ ਬਦਲੋ।
